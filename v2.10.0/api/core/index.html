Core API

    Core Messages and Errors

    HTTP.Request — Type
    Request(method, target; headers=Headers(), body=nothing, trailers=Headers(),
        host=nothing, content_length=-1, proto_major=1, proto_minor=1,
        close=false, context=RequestContext(), copyheaders=true)
Request(method, target, headers[, body])

    An HTTP request: what a server handler receives, and what the client sends.

    • headers, trailers: anything Headers accepts. They are copied unless copyheaders = false and they are Headers collections; the request then uses them directly, so do not touch them while the request is in use.
    • body: a String, a byte vector, an AbstractBody, or nothing.
    • host: the authority sent as the HTTP/1 Host header or HTTP/2 :authority.
    • content_length: the body length in bytes. -1 computes it for a String, byte-vector, or empty body, and means unknown for other bodies.
    • proto_major, proto_minor: the HTTP version.
    • close: close the connection after this request.
    • context: the request's RequestContext.

    req.context returns the context's application data as a Dict{Symbol,Any}; use get_request_context for the RequestContext itself.

    source
    HTTP.Response — Type
    Response(status, [body]; headers=Headers(), reason="", trailers=Headers(),
         content_length=-1, proto_major=1, proto_minor=1, close=false,
         request=nothing)
Response(status, headers, body)
Response(body)

    An HTTP response: what a server handler returns, and what the client returns.

    body, passed by position or as a keyword, may be a String, a byte vector, an AbstractBody, or nothing. A String or byte vector is stored as is, so one Response can be returned for many requests. content_length defaults to the length of such a body. request is the request that produced the response. Response(body) uses status 200.

    A client response also has response.url, the final URL after redirects.

    source
    HTTP.Headers — Type
    Headers()
Headers(items)
Headers(pairs...; kwargs...)

    An ordered vector of String => String header pairs.

    Header names match in any case (RFC 9110 §5.1): header, setheader, removeheader, haskey, and the other lookups ignore case, and each name keeps the spelling it was stored with. HTTP/1 sends names in that spelling; HTTP/2 sends them in lowercase. Headers read from the network are stored in canonical_header_key form, such as Content-Type, so a response looks the same over HTTP/1 and HTTP/2.

    items may be a vector, dictionary, or tuple of pairs, and keyword arguments add more headers. The input is copied, and a header with the same name as the one before it is joined onto it, as in appendheader. Headers(n::Integer) returns an empty collection with room for n headers.

    source
    HTTP.RequestContext — Type
    RequestContext(; deadline_ns=0)

    Cancellation, deadline, and application data for one request. Pass one to a client call with the context keyword; get_request_context returns the context of a request a server is handling.

    deadline_ns is an absolute time_ns() value, or 0 for no deadline. A client request still running at the deadline throws TimeoutError, and cancel! makes it throw CanceledError.

    Application data is stored under Symbol keys:

    ctx = HTTP.RequestContext()
ctx[:request_id] = "abc"
get(ctx, :request_id, nothing)

    HTTPError

    Abstract supertype for HTTP-specific exceptions raised by HTTP.jl.

    source
    HTTP.ParseError — Type
    ParseError

    Raised when byte-level HTTP syntax cannot be parsed. This is used for malformed request/status lines, invalid header syntax, truncated framed bodies, and other wire-format failures where the peer did not send valid HTTP.

    source
    HTTP.ProtocolError — Type
    ProtocolError

    Raised when the bytes are syntactically valid but violate higher-level HTTP rules. Examples include mismatched Content-Length values, impossible frame ordering, or unsupported control-flow states in the client/server stacks.

    source
    HTTP.CanceledError — Type
    CanceledError

    Raised when request processing is canceled explicitly through RequestContext. Unlike ParseError and ProtocolError, this usually reflects local control flow rather than a bad peer.

    source
    HTTP.TimeoutError — Type
    TimeoutError

    Raised when a client timeout or deadline expires.

    Fields:

    • operation::String: "connect" or "tls_handshake" when connect_timeout expired, "websocket handshake" for a WebSocket handshake, and "request" for the other timeouts and for deadlines.
    • timeout_ns::Int64: the timeout that expired, in nanoseconds, or 0 when it is not known.
    • elapsed_ns::Int64: the time spent before it expired, in nanoseconds, or 0 when it is not known.
    source
    HTTP.HTTPTimeoutError — Type
    HTTPTimeoutError

    Another name for TimeoutError.

    source
    HTTP.StatusError — Type
    StatusError

    Raised by request and the verb helpers for a response with status 300 or above that is not a redirect, unless status_exception = false.

    Fields:

    • status::Int16: the response status.
    • response::Response: the response, including its body.
    source
    HTTP.TooManyRedirectsError — Type
    TooManyRedirectsError

    Raised when a request reaches its redirect limit and gets another redirect. limit is the limit and response is the last redirect response.

    source

    HTTP.DNSError — Type

    HTTP.TLSHandshakeError — Type
    TLSHandshakeError(cause)

    Raised when a TLS handshake fails (other than a handshake timeout, which surfaces as TimeoutError with operation = "tls_handshake"). TLS failures after connection setup surface as TLSTransportError instead.

    HTTP.TLSTransportError — Type
    TLSTransportError(cause)

    HTTP.mkheaders — Function
    mkheaders(headers_input) -> Headers

    Body Types and Streamed Payloads

    HTTP.AbstractBody — Type
    AbstractBody

    Supertype of request and response bodies that are read as a stream.

    A subtype implements body_read!, body_close!, and body_closed.

    source
    HTTP.CallbackBody — Type
    CallbackBody(read_cb, close_cb)

    A body produced by a function. read_cb(dst::Vector{UInt8}) fills the start of dst and returns the number of bytes written, or 0 at the end of the body. close_cb() runs once, when the body is closed. A CallbackBody can be read only once.

    source
    HTTP.nobody — Constant

    An empty Vector{UInt8} to pass as a body that has no bytes. It is shared, so do not modify it.

    source
    HTTP.body_read! — Function
    body_read!(body, dst) -> Int

    Read up to length(dst) bytes of body into dst and return how many were read, or 0 at the end of the body.

    source
    HTTP.body_close! — Function
    body_close!(body)

    Close body and release what it holds. Closing a closed body does nothing, so it is safe to call in a finally block.

    source
    HTTP.body_closed — Function
    body_closed(body) -> Bool

    Return true once body_close! has closed body. Reading a body to the end does not close it.

    source
    HTTP.read_request — Function
    read_request(io; max_line_bytes=64*1024, max_header_bytes=1024*1024) -> Request

    Read one HTTP/1 request head from io and return it as a Request whose body reads the rest of the request from io. max_line_bytes limits each line and max_header_bytes the whole head. Throws ParseError or ProtocolError for an invalid request.

    source
    HTTP.write_request! — Function
    write_request!(io, request)

    Write request to io in HTTP/1.1 format, with its body.

    The Host header comes first (RFC 9110 §7.2), taken from the request's Host header or else from request.host. A body of known length is sent with Content-Length, and any other body with chunked encoding, the only framing that carries trailers.

    source
    HTTP.write_response! — Function
    write_response!(io, response)

    Write response to io in HTTP/1.1 format, with its body. No body is written for 1xx, 204, and 304 responses, or when response.request is a HEAD request.

    source
    HTTP.trailers — Function
    trailers(body)

    Return a copy of the trailers that ended a chunked body, or empty Headers for other bodies. Read the body to the end first.

    HTTP.Form — Type
    Form(parts; boundary, type=:formdata) <: IO

    A multipart request body. parts is a collection of name => value pairs. An IO value is streamed (an open file is sent with its file name, and a Multipart with its own name and content type); any other value is sent as string(value). type = :mixed builds a multipart/mixed body instead of multipart/form-data. A request with a Form body gets the matching Content-Type header from content_type.

    source
    HTTP.Multipart — Type
    Multipart(filename, data, contenttype="", contenttransferencoding="", name="") <: IO

    One part of a multipart body, with its content in the IO data. filename may be nothing, and an empty contenttype is detected from the data when the part is sent. The parse_multipart functions return Multiparts, and Form accepts them as values.

    source
    HTTP.Batch — Function
    Batch(parts; boundary) -> Form

    Build a multipart/mixed body, the format of batch APIs such as OData $batch. parts is a vector of Multiparts or a collection of name => value pairs, as for Form with type = :mixed.

    parts = [
    HTTP.Multipart(nothing, IOBuffer("GET /users/1 HTTP/1.1\r\n\r\n"), "application/http"),
    HTTP.Multipart(nothing, IOBuffer("GET /users/2 HTTP/1.1\r\n\r\n"), "application/http"),
]
response = HTTP.post(url, [], HTTP.Batch(parts))
    source

    HTTP.parse_multipart_form — Function
    parse_multipart_form(content_type_header, body) -> Union{Vector{Multipart}, Nothing}
parse_multipart_form(message) -> Union{Vector{Multipart}, Nothing}

    Parse a multipart/form-data body, using the boundary in content_type_header. The message form reads the Content-Type header and body of a Request or Response, such as the request in a serve! handler.

    Returns nothing when the content type is not multipart/form-data or there is no body. Each Multipart has the part's name, filename (or nothing), contenttype, and its content as the IO data.

    Examples

    julia> body = Vector{UInt8}(
           "--boundary\r\n" *
           "Content-Disposition: form-data; name=\"greeting\"\r\n\r\n" *
           "hello\r\n" *
           "--boundary\r\n" *
           "Content-Disposition: form-data; name=\"file\"; filename=\"a.txt\"\r\n" *
           "Content-Type: text/plain\r\n\r\n" *
           "file contents\r\n" *
           "--boundary--\r\n");

julia> parts = HTTP.parse_multipart_form("multipart/form-data; boundary=boundary", body);

julia> length(parts)
2

julia> parts[1].name, String(read(parts[1].data))
("greeting", "hello")

julia> parts[2].name, parts[2].filename, parts[2].contenttype
("file", "a.txt", "text/plain")

julia> String(read(parts[2].data))
"file contents"

    Inside a server handler, pass the request directly:

    HTTP.serve!("127.0.0.1", 8080) do request
    parts = HTTP.parse_multipart_form(request)
    parts === nothing && return HTTP.Response(415, "expected multipart/form-data")
    return HTTP.Response(200, "received $(length(parts)) part(s)")
end

    Proxy Configuration

    HTTP.ProxyConfig — Type
    ProxyConfig(url; no_proxy=nothing)
ProxyConfig(; http=nothing, https=nothing, all=nothing, no_proxy=nothing, env=false)

    The proxy settings of a Transport or a request. ProxyConfig() connects directly.

    http is the proxy for http:// URLs, https the proxy for https:// URLs, and all the proxy for either when the other is not set; ProxyConfig(url) sets all. no_proxy is a NoProxy, or anything it accepts, naming hosts to reach directly. With env = true, settings that are not given come from the HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, and NO_PROXY environment variables, in upper or lower case.

    Proxy URLs may use http://, socks5://, or socks5h://; with either SOCKS scheme, the proxy resolves host names. An https:// proxy URL is accepted, but a request through it throws ArgumentError.

    source
    HTTP.ProxyURL — Function
    ProxyURL(url; no_proxy=nothing) -> ProxyConfig

    Return a ProxyConfig that sends every request through the proxy at url, except requests to the hosts in no_proxy.

    source
    HTTP.ProxyFromEnvironment — Function
    ProxyFromEnvironment() -> ProxyConfig

    Return a ProxyConfig read from the HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, and NO_PROXY environment variables, in upper or lower case. The variables are read once, when it is called.

    source
    HTTP.NoProxy — Type
    NoProxy(spec)
NoProxy()

    The hosts that a ProxyConfig reaches without its proxy, in the format of the NO_PROXY environment variable. spec is a comma-separated string or a vector of entries: host names, domain suffixes, IP addresses, CIDR ranges, or any of these with a :port. "*" matches every host. localhost and loopback addresses always match.

    HTTP/2 Configuration

    HTTP.HTTP2Settings — Type
    HTTP2Settings(; initial_window_size=65535, connection_window_size=65535)

    HTTP/2 receive windows, passed as http2_settings to a Client or to serve! and listen!.

    • initial_window_size: the receive window of each stream, sent as SETTINGS_INITIAL_WINDOW_SIZE (RFC 9113 §6.5.2). Values from 1 to 2^31 - 1 are allowed, so it can also be lowered to slow down senders.
    • connection_window_size: the receive window shared by all streams on a connection, from 65535 to 2^31 - 1.

    Both default to 65535, the protocol default. One stream can move at most about window / round-trip time bytes per second, so raise them for large transfers over links with high latency.
